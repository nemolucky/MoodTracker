# Mood Tracker — дневник настроения

## Назначение

Mood Tracker — приложение для ведения дневника настроения и отслеживания эмоционального состояния.
Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:
* просматривать записи настроения в браузере;
* просматривать информацию о конкретной записи настроения;
* просматривать список типов настроений в браузере;
* просматривать информацию о конкретном настроении;
* отслеживать динамику и статус настроения по шкале 0-10;
* находить записи по дате;
* фильтровать записи по оценке;
* сортировать записи по оценке;
* вести учёт нескольких пользователей;
* хранить данные между запусками приложения.

## Используемые технологии

* Python 3;
* Django 5.2 — веб-фреймворк;
* HTML — разметка веб-страниц;
* CSS и Bootstrap 5.3 — оформление страниц;
* pytest — автоматизированные тесты;
* flake8 — проверка качества кода.

## Целевая аудитория

Люди, которые хотят отслеживать своё эмоциональное состояние и видеть динамику настроения со временем.

## Предметная область

Основными объектами предметной области являются:
* пользователь (`User`);
* запись о настроении (`MoodEntry`);
* тип настроения (`Mood`);
* фактор влияния (`Factor`).

Пользователь создаёт записи о своём настроении за определённую дату, указывая оценку от 0 до 10, комментарий, тип настроения и сопутствующие факторы влияния.

## Основные сущности

### User — пользователь

Объект `User` представляет пользователя системы.

Основные атрибуты:
* `id` — уникальный идентификатор пользователя;
* `name` — имя пользователя;
* `email` — адрес электронной почты (необязательный).

Основные методы:
* `__str__()` — строковое представление пользователя;
* `from_data()` — создание объекта `User` из набора данных JSON.

### MoodEntry — запись настроения

Объект `MoodEntry` представляет запись о настроении пользователя.

Основные атрибуты:
* `id` — уникальный идентификатор записи;
* `entry_date` — дата записи;
* `score` — оценка настроения (0-10);
* `comment` — комментарий пользователя;
* `user` — объект `User`;
* `mood` — объект `Mood` (необязательный);
* `factors` — список объектов `Factor`.

Основные методы:
* `get_status()` — текстовое описание статуса дня («Хороший день» / «Нейтральный день» / «Плохой день»);
* `validate_score()` — проверка корректности оценки (0-10);
* `__str__()` — строковое представление записи.

### Mood — тип настроения

Объект `Mood` представляет категорию эмоционального состояния.

Основные атрибуты:
* `id` — идентификатор настроения;
* `name` — название настроения;
* `description` — описание настроения.

Основные методы:
* `__str__()` — строковое представление настроения;
* `from_data()` — создание объекта из словаря.

### Factor — фактор влияния

Объект `Factor` представляет фактор окружения, влияющий на настроение.

Основные атрибуты:
* `id` — идентификатор фактора;
* `name` — название фактора;
* `category` — категория (Здоровье, Работа, Социум и т.д.).

Основные методы:
* `__str__()` — строковое представление фактора;
* `from_data()` — создание объекта из словаря.

## Страницы веб-интерфейса

* `/` — главная страница: описание приложения и навигация (view-функция `index()`);
* `/entries/` — список записей настроения: объекты `MoodEntry` из `data/entries.json` (view-функция `entries()`);
* `/entries/<int:entry_id>/` — страница записи настроения (view-функция `entry_detail()`);
* `/moods/` — список типов настроения: объекты `Mood` из `data/moods.json` (view-функция `moods()`);
* `/moods/<int:mood_id>/` — страница типа настроения и связанных записей (view-функция `mood_detail()`).

Если запись настроения или тип настроения с указанным идентификатором не найдены, соответствующая страница возвращает код статуса 404. Несуществующие маршруты также обрабатываются кастомной страницей ошибки 404 (`page_not_found()`).

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка записей настроения;
* просмотр детальной информации о записи настроения;
* просмотр списка типов настроения;
* просмотр детальной информации о типе настроения и связанных записях;
* отображение статуса дня и цветовых индикаторов-бейджей по оценке.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии. В веб-интерфейсе они появятся, когда будут добавлены формы и POST-запросы:
* добавление новой записи настроения через веб-форму;
* поиск записей по дате;
* фильтрация записей по минимальной оценке;
* сортировка записей по оценке;
* добавление пользователя;
* добавление настроений и факторов.

## Хранение данных

Данные приложения хранятся в JSON-файлах:
* `data/entries.json`;
* `data/users.json`;
* `data/moods.json`;
* `data/factors.json`.

При загрузке данные из JSON преобразуются в объекты `User`, `MoodEntry`, `Mood` и `Factor`.
При сохранении объекты преобразуются в данные JSON.
Для связи записи с пользователем, настроением и факторами в `entries.json` используются их идентификаторы: `user_id`, `mood_id`, `factor_ids`.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3).
Отвечает за:
* запуск консольного приложения;
* отображение консольного меню;
* интерактивное получение данных от пользователя;
* реализацию консольных сценариев.

### `moodtracker/`
Пакет настроек Django-проекта:
* `settings.py` — настройки проекта (регистрация приложений, локализация `ru-RU`, часовой пояс `Europe/Moscow`, хосты);
* `urls.py` — маршрутизация верхнего уровня (подключение маршрутов приложений через `include()`, настройка `handler404`);
* `asgi.py`, `wsgi.py` — точки взаимодействия с серверами.

### `homepage/`
Django-приложение, отвечающее за главную страницу:
* `views.py` — вспомогательная функция `page()` (общий HTML-каркас с подключением Bootstrap 5.3 CDN и навигацией), view-функция главной страницы `index()` и обработчик ошибки `page_not_found()`;
* `urls.py` — маршрут главной страницы.

### `entries/`
Django-приложение, отвечающее за записи настроения:
* `views.py` — view-функции `entries()` (список) и `entry_detail()` (карточка записи);
* `urls.py` — маршруты приложения;
* `models.py` — Django-модели (будут заполнены в следующих практических работах).

### `moods/`
Django-приложение, отвечающее за типы настроения:
* `views.py` — view-функции `moods()` (список) и `mood_detail()` (карточка настроения);
* `urls.py` — маршруты приложения;
* `models.py` — Django-модели (будут заполнены в следующих практических работах).

### `models/`
Классы предметной области и функции работы с ними (пакет ПР3):
* `entries.py` — класс `MoodEntry` и функции работы с записями;
* `users.py` — класс `User` и функции работы с пользователями;
* `moods.py` — класс `Mood` и функции работы с типами настроения;
* `factors.py` — класс `Factor` и функции работы с факторами.

### `storage.py`
Отвечает за загрузку и сохранение данных:
* JSON → объекты Python;
* объекты Python → JSON.

### `utils.py`
Содержит вспомогательные функции консольного безопасного ввода (`input_int`, `input_date`).

### `tests/`
Содержит автоматизированные тесты проекта.

## Запуск приложения

Веб-версия (Django):
```text
python manage.py runserver
```

После запуска открыть в браузере адрес:
```text
http://127.0.0.1:8000/
```

```text
python main.py
```
